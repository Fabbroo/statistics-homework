From Wallet Seed to Ethereum Address

Analysis of the cryptographic pipeline used in Ethereum wallets.

Overview

Ethereum wallets do not directly generate an address from a password or from a single cryptographic algorithm. Instead, they use a pipeline of specialized standards and cryptographic primitives, each designed for a different purpose. The process starts with a human-readable mnemonic phrase and ends with a checksummed Ethereum address.
The main stages are: mnemonic generation (BIP-39), hierarchical key derivation (BIP-32 and BIP-44), public-key cryptography (secp256k1), hashing (Keccak-256), and checksum encoding (EIP-55).

    ↓ BIP-39

    ↓ BIP-32 / BIP-44

    ↓ secp256k1

    ↓ Keccak-256

    ↓ EIP-55
Checksummed Address

BIP-39

BIP-39 was introduced to provide a human-friendly method of backing up cryptocurrency wallets. Instead of recording long hexadecimal strings, users can store a list of 12, 15, 18, 21, or 24 words.
For example: "fish dolphin shark sea ..."
The mnemonic is then converted into a binary seed that can be used for deterministic wallet generation.

BIP-32

This is a key derivation algorithm, which means BIP-32 outputs new keys based on an input key. It is different from a key generation algorithm which starts from randomness to generate a key.
BIP-32 introduced Hierarchical Deterministic (HD) wallets. Instead of generating unrelated private keys, a single master seed can deterministically generate an entire tree of keys.
This means one backup phrase can be used to recover every account/address that belongs to a wallet.

BIP-44

Just as BIP-32, BIP-44 is a key derivation algorithm. BIP-44 standardized how HD wallets organize derived keys. It defines a path structure:
m / purpose' / coin_type' / account_number' / change / address_index
The path used in Ethereum is: m / 44'/ 60'/ 0'/ 0 / 0; where: 44' = BIP-44, 60' = Ethereum coin type, 0' = first account, 0 = external addresses, 0 = first address.

secp256k1

For public-key cryptography, Ethereum uses the elliptic curve secp256k1.
The private key k is a 256-bit integer and the corresponding public key is obtained through elliptic-curve scalar multiplication: Q = kG.
The security relies on the Elliptic Curve Discrete Logarithm Problem (ECDLP), which makes recovering k from Q computationally infeasible.

Keccak-256

This is a cryptographic hashing algorithm. That means that this algorithm provides: determinism, collision resistance and avalanche effect.
Ethereum uses Keccak-256 to derive addresses from public keys by hashing the public key and using the last 20 bytes of the resulting hash as the address.

EIP-55

This is a checksum mechanism, which means it is used to verify if the data is correct.
To provide this functionality, Ethereum uses EIP-55.
Ethereum addresses are usually written in hexadecimal, for example:
0x742d35Cc6634C0532925a3b844Bc454e4438f44e
EIP-55 uses uppercase and lowercase letters as a checksum mechanism and the capitalization pattern is derived from a hash of the address itself. If a user accidentally changes or mistypes a character, the checksum is likely to fail. So it protects against human error.

Why Ethereum uses multiple cryptographic techniques?

Ethereum uses multiple cryptographic techniques because there isn't a single cryptographic primitive which is able to provide all that's needed for Ethereum's system to work properly.
Every cryptographic primitive used serves best the purpose it is required to fulfill.
